# 永久親子追蹤：操作及還原指南

## ID 代表甚麼

`dyad_id` 追蹤同一孩子的家庭。換填卷家長仍沿用；兄弟姊妹分開。這個 ID 不證明兩輪填卷家長是同一成人，BD 的判斷保留。

永久提交 ID、提交內容版本、當版孩子群組 ID 及永久家庭 ID 是不同欄位。原始四份合併 Excel 不會加入追蹤 ID。Qualtrics 不會自動帶回此 ID，新 T1 仍先經身份配對及人工核實。

## 1. 更新資料及發布

沿用 `Prepare Batch.command`、`Run Pipeline.command`。來源登記、本機資料庫及審核歷史須保留。新快照可以增加或移動記錄，但不能靜默修改、刪除已登記的合併檔記錄。

Pipeline 先完成原有身份、人工決定、重填及輪次選擇，再處理永久登記。新 ID 先預留及備份，驗證後才發布。失敗重試沿用預留 ID，不重新編號。

E／F／EF 新增 `dyad_id`、`registration_state`；已有欄位及研究計數方式不變。`dyad_tracking.xlsx` 的「家庭追蹤」包含當版對應，「待裁定」列出不能自動啟用的項目。

正式輸出的位置以 `config.local.json`／`config.merged.json` 的 `release_dir` 為準。本機設定使用 state 目錄下的 `releases`，放在同步資料夾以外，避免 iCloud 自動卸載造成讀取超時。原有版本保留在歷史路徑；四份來源的位置不變。Dashboard 及操作中心會讀取目前設定，不要用歷史資料夾推定最新版本。

| 狀態 | 意義 | 邀請 |
|---|---|---|
| active | 已發布、唯一且無未解決的身份矛盾 | 須再通過角色、日期及行政狀態檢查 |
| new | 唯讀預覽中可首次登記；尚未發 ID | 不可 |
| suspended | 已有 ID 涉及證據變更、群組拆分、合併或其他歧義 | 不可 |
| awaiting_registration | 未能安全建立正式登記，例如首次 E 有矛盾候選 | 不可 |
| reserved | ID 已預留但尚未成功發布 | 不可 |
| retired | 明確停用，歷史及 ID 保留 | 不可；不自動重新發 ID |

待裁定項目不一定是另一個家庭，不能把追蹤表行數當作已確認孩子人數。研究樣本可以保留，但永久登記／邀請暫停。

## 2. 同事查看 dashboard

開啟「親子追蹤」。可以搜尋 ID、篩選登記狀態及 T1 完成情況，下載不包含完整聯絡資料的摘要。選擇 ID 查看登記及邀請歷史。

研究對應使用目前發布版本。行政狀態及邀請紀錄可能更新得較早，頁面分開標示，不改動研究統計。

| 欄位 | 解讀 |
|---|---|
| 各角色 T0／選定 T1 | 目前研究版本選定的回應，不是首次登記錨點 |
| 最早 T1 日期 | 該角色目前 T0 加研究規定的 90 日，保留日期來源 |
| 共同邀請建議日期 | 兩個角色最早日期中較遲者；不是新的配對或資格規則 |
| 其他回應數 | 該已確認群組、該角色除選定 T0 外的回應，包括未選定或未合資格提交 |
| 未滿 90 日回應 | 保留為短間隔 follow-up；不算完成合資格 T1 |
| 其他後續／重填 | 包括未選定的其他後續及短期重填；原記錄仍可追查 |
| 待核實身份候選數 | 涉及此群組的待審比較宗數，不是已收到的獨立參加者人數 |
| 成人身份 | 同一成人、成人不同／關係更換，或未確認；年份差異未必能證明換人 |

已收到問卷、選定合資格 T1、曾邀請及保存發送紀錄是不同狀態。尚未確認歸屬的回應不自動計入家庭完成。

## 3. 指定執行者匯出邀請及記錄結果

雙擊 `Dyad Centre.command` 開啟中文操作中心：

1. 「預覽登記／待裁定」：產生本機登記預覽及待裁定 Excel。
2. 「匯出邀請清單」：只列有效已發布登記中仍需 T1 的角色，有聯絡來源、版本、日期依據及歷史發送次數。清單含個人資料，限指定執行者使用。
3. 同事按研究安排自行聯絡家庭。程式不發送訊息。
4. 「保存實際邀請紀錄」：指定 ID、學生或家長、實際日期、執行者、聯絡方式、結果及理由。也可明確停止或恢復邀請。
5. 程式驗證目前版本及清單證據，備份後保存歷史。已完成 T1、登記暫停、日期不明、已停止或證據失效時，不接受新的發送紀錄。實際日期不能在未來。較早發出的邀請仍如實保存，另標記早於該角色 T0＋90 日；不能因此把回應當作合資格 T1。

「保存」只寫行政紀錄，不改正式身份、輪次、量表或發布版本。實際有多次邀請時逐次保存；同一事件及同一操作重試不重複記錄。清單的日期時間以原資料的標準時間值保存，須留意 `+00:00` 是 UTC。

人工決定或核實標記一旦套用／更正，而尚未重跑發布，邀請匯出及新增邀請紀錄會停止，提示先重跑及發布。這項檢查以目前發布版本的主備份為基線，涵蓋拒配、身份／聯絡修正及核實標記；未套用的審核答案不會因此阻止邀請。已成功保存的同一操作仍可重試核對，不會新增事件。

還原時若審核工作區比主備份更新，包含主資料庫尚未恢復的已套用批次，邀請也會停止。先用既有審核中心恢復／核對該批次的主資料庫裁定，重跑及發布後才重新匯出。

操作中心先保存有固定操作 ID 的本機請求 JSON。出錯或中斷後，以同一檔案重試，不能另造新操作來取代未查明的操作。

命令列入口：

```sh
./.venv/bin/python -m study2 dyad-console
./.venv/bin/python -m study2 dyad-preview --output preview.xlsx
./.venv/bin/python -m study2 dyad-invitations --output invitations.xlsx
./.venv/bin/python -m study2 dyad-record-invitation saved-request.json
./.venv/bin/python -m study2 dyad-report
```

## 4. Jarvis 裁定身份登記

先使用既有審核及修正工具解決研究身份，重跑並發布。永久登記裁定不能直接消除研究身份矛盾，不能把原 ID 指向沒有已核實提交關聯的另一孩子。

操作中心的裁定功能要求 Jarvis、具體理由、目前發布版本及預覽的身份證據：

- 保留／重新對應：保留原 ID，確認新的唯一群組歸屬。
- 合併：明確指定保留 ID及被合併 ID。被合併 ID 停用，保留別名及完整歷史。
- 拆分：明確指定哪個孩子保留原 ID，其餘孩子建立新 ID。所有目標須已有確認 T0 親子樣本。
- 停用：保留 ID及歷史，停止使用；不自動發新 ID 取代相同家庭。

裁定採短交易及固定操作 ID，有前後備份。裁定後重新執行及發布才更新研究版本中的對應。版本、簽章、目標或理由不符時拒絕保存。

```sh
./.venv/bin/python -m study2 dyad-adjudicate saved-adjudication.json
```

首次原始 T0 錨點不可更改；新追蹤依據保存在有歷史的對應及裁定中。

合併後可以在 dashboard 搜尋舊 ID，找到已批准的現在對應，連同舊 ID 的邀請及停止／恢復紀錄一起查看。多次合併的別名可以逐層追查。拆分的 ID 歸屬必須明確裁定，不由最初錨點或字母排序自動決定。

## 5. 備份、回退及還原

主資料庫包含原始提交、研究版本和追蹤登記。追蹤備份另保護每次研究發布後新增、尚未發布的行政及審核工作。

- 每次登記預留、裁定、邀請紀錄及發布均保存追蹤工作區。
- 每個追蹤 bundle 包含 `tracking.json`、指紋 manifest，以及存在時的完整 `review.sqlite`。
- 同一檔案系統上的追蹤及審核備份以 hard link 共用同一份不可修改的 SQLite 快照；刪除其中一個路徑不影響另一份。跨檔案系統或不支援 hard link 時保存獨立副本。運行中的 `review.sqlite` 永遠不與備份共用檔案，還原仍建立獨立副本。
- 每個 pipeline 發布亦有完整 `backup.sqlite`。
- 本機 `DYAD_LEDGER.json` 指向最近保存的行政歷史。不要因回退研究版本而刪除它或追蹤備份。
- 還原舊主資料庫後，程式會檢查是否遺漏已登記 ID、邀請或裁定。有遺漏不能繼續發 ID或邀請。

研究回退：

```sh
./.venv/bin/python -m study2 rollback PREVIOUS_RELEASE
```

回退保留較新的登記、邀請及裁定歷史。回退版本中的對應是歷史資料，受控邀請仍按現有行政歷史重新核實；可能暫停曾有新增或修正的家庭。

完整還原到新資料夾：

```sh
./.venv/bin/python -m study2 dyad-restore TRACKING_BUNDLE --main-backup FULL_BACKUP --destination NEW_STATE_DIRECTORY
```

必須選擇完整主資料庫備份及最新一致的追蹤 bundle。程式驗證指紋、SQLite 完整性及歷史衝突，把追蹤與審核工作還原到新資料夾，不覆寫正在使用的資料庫。

若主備份已有較新的登記、裁定、別名或邀請事件，而追蹤 bundle 缺少這些歷史，程式會在建立還原資料夾前拒絕操作。已停用的登記也不能被較舊 bundle 恢復為有效。請改用包含完整較新歷史的追蹤備份，不能刪除事件或改狀態繞過檢查。

新資料夾保留原 bundle。若較新的研究 run 不在舊主備份，相關每版對應保留在原 bundle，不能捏造研究 run。先核對並恢復需要的來源／主備份，再做唯讀登記預覽及完整 pipeline 檢查，確認後才切換設定或恢復操作。

操作中心選項 5 或以下入口建立額外備份：

```sh
./.venv/bin/python -m study2 dyad-backup
```

### 清理儲存空間

清理先保護兩個運行中的資料庫、目前發布版本，以及 `DYAD_LEDGER.json` 指向的完整追蹤 bundle。審核答案、人工裁定及永久登記不按日期自動刪除。

已完成用途的驗證資料庫，須先核對其中的提交 ID、來源版本、原始／標準化答值及人工裁定均已保存在主資料庫，才刪除驗證副本。升級前的獨立基線可轉成 `.sqlite.gz` 冷存檔；逐位元驗證解壓後的 SHA-256 及檔案大小，再移除未壓縮原檔。保留相鄰的驗證紀錄及原有升級報告。

發布驗證、人工裁定基線核對及還原指令支援 `.sqlite.gz`，在同步資料夾外的私有暫存位置解壓，核對原始 SHA-256，完成後清除暫存 SQLite。指令可指定 gzip 路徑；指定原 `.sqlite` 路徑時，若原檔已不存在，會尋找相鄰的 `.sqlite.gz`。原 `backup.sha256.json` 保留未壓縮內容的指紋。共用儲存空間的歷史備份不能直接修改；須還原到獨立副本。

清理只保留最新完整主備份時，較舊版本的輸出及主資料庫內的研究歷史仍保留，但已移除完整備份的版本不能再直接還原或通過原有回退驗證。每個被清理版本以 `backup.retention.json` 記錄原因及保留備份的位置。最新行政／審核 bundle 與完整主備份是不同用途，不隨舊研究備份一併刪除。

## 6. 驗證與故障處理

若更新被阻止，保留來源、已保存請求及錯誤訊息，不重設來源代號、刪除歷史或放寬配對規則。需要重新核實的個案交回既有審核流程。

程式測試使用合成資料，包括重跑、移位、共享聯絡、換家長、合併／拆分、證據變動、操作重試、發布失敗、行政歷史回退及備份還原。真實資料發布前另逐項比較提交 ID、版本、答案、人工決定、樣本組成及量表。

程式、通用文件與本機私有資料分開。邀請清單、登記明細、實際請求、備份及驗證報告不得加入 Git 或上傳。
